# External proxy configuration

The application owns its file-based deployment configuration and generates one
native Traefik dynamic configuration. Application agents must not access or modify
the central SSL/proxy project. Central integration is performed separately.

## Configuration

Copy `.env.example` to `.env` when preparing another checkout. Configure the real
public origin before generating a deployment file. No credentials are required.
The private `.env` is not included in Git or repository archives.

| ENV input | Meaning |
| --- | --- |
| `MADRASI_PORT` | Game backend port, assigned 9000 |
| `MADRASI_PATH` | Complete game path, assigned `/madrasi/` |
| `MADRASI_REFERENCE_PORT` | Flash reference backend port, assigned 9001 |
| `MADRASI_REFERENCE_PATH` | Complete reference path, assigned `/madrasi/reference/` |
| `MADRASI_PUBLIC_ORIGIN` | Public scheme, hostname and optional port, without a trailing slash |

The ENV format is deliberately small: one unquoted `KEY=value` per line, with
blank lines and full-line `#` comments. No expansion, shell evaluation, duplicate
keys, unknown keys or process-environment overrides are accepted. Missing or invalid
values fail safely. Servers and developer URL consumers use the same file-only
Node reader in `scripts/internal/deployment-config.mjs`; the PowerShell generator
reads the same five keys directly, without invoking Node or application helpers.
There is no second configuration registry.

Port groups are 9000–9019 applications/APIs, 9020–9039 agents/workers,
9040–9059 monitoring, 9060–9079 databases/storage, 9080–9089 debugging and
9090–9099 reserved. This application allocates only 9000 and 9001. Diagnostic
browser endpoints and temporary test servers are not new deployment services.

## Endpoints

Append these complete paths to the configured public origin. The backend receives
the identical path; neither Traefik nor forwarded-prefix handling strips or adds it.

| Component | Complete path | Loopback backend |
| --- | --- | --- |
| Source game | `/madrasi/` | HTTP port 9000 |
| Development catalogue | `/madrasi/development/catalog/` | Same game backend |
| Development verification | `/madrasi/development/verification/` | Same game backend |
| Static game package | `/madrasi/dist/site/` | Same game backend |
| Standalone package | `/madrasi/dist/standalone/` | Same game backend |
| Compiled development modules | `/madrasi/build/` | Same game backend |
| Resources | `/madrasi/assets/` | Same game backend |
| Flash reference, Ruffle and optional probe files | `/madrasi/reference/` | HTTP port 9001 |

Both listeners remain bound to `127.0.0.1`. Direct local browsing uses
`http://127.0.0.1:9000/madrasi/` or
`http://127.0.0.1:9001/madrasi/reference/`. The bare listener root is not a game
route. The main backend does not serve the reference subtree. Relative links and
asset URLs preserve the prefix, and missing directory slashes redirect within it.
The game router explicitly excludes the reference subtree; no priorities resolve
overlapping rules.

The source game needs the existing compiled development files; the catalogue needs
the existing resource exports. Reference playback needs the separately installed
Ruffle files, and optional probes need their generated SWFs. These prerequisites
are not inspected, installed or generated by the proxy generator. Missing files
can still produce 404 responses. Both routers are emitted regardless of running
state or resource availability.

The legacy score integration is a client, not an application backend. It has no
configured POST endpoints by default. Do not invent a score service or export the
historical remote PHP URLs as local routes. The distribution test's port-0 server
is an ephemeral test fixture, not a stable component; it remains unexported and is
not converted into a permanent service.

## Generate

Run `generate-external-proxy-config.cmd` from any working directory. Its quoted
PowerShell path supports spaces and its exit code is propagated. The script writes
only `config/external-proxy.generated.yaml`; no application, browser or network
inspection is performed. The public origin is validated but is deliberately not
exported as a public Host rule.

On Windows, `.env`, the output directory, generated YAML and temporary file have
restricted ACLs for the current operator and SYSTEM. The temporary file is created
inside the protected directory, flushed, then atomically replaces the previous
file. Failure returns a nonzero exit code without exposing configuration or
exception contents. Git exclusions supplement filesystem permissions.

The central operator must arrange read access for its actual service account if
different. Do not broaden access to all users or copy private configuration into
frontend assets. The generator is Windows-specific and requires ACL and atomic
replacement support on the destination filesystem.

## Security boundary and limitations

Central external BasicAuth is mandatory for every exported route, including all
assets, downloads and the reference component. This YAML is not a standalone
secure deployment: the central integration must attach that protection to both
routers. It must remove external Authorization before forwarding. The application
never reads, stores or generates external credentials. The central project is
outside this task's scope.

These static backends have no platform login or internal token gate. None is added;
there is no Bearer translation, cookie login, service principal or administrator
bypass. Direct local access remains unauthenticated. Only GET and HEAD are served;
no state-changing HTTP API is introduced. Browser-local scores and preferences
remain in localStorage, and the legacy score client remains unconfigured.

Applications sharing a scheme, hostname and port share a browser origin. Paths,
different BasicAuth passwords and cookie scoping do not isolate their scripts or
localStorage. Existing UI text uses textContent in the inspected paths; that is
not a complete XSS audit. The reference player retains its existing inline-script
and WebAssembly CSP allowances. External score service CSRF/authentication remains
an unresolved integration, not something the proxy generator can establish.

Backends use HTTP loopback with preserved Host handling. No TLS verification is
disabled. No buffering, WebSocket-header overrides, third-party authentication
adaptations, response rewriting or additional proxies are introduced. Existing
GitHub Pages/Azure static publishing and standalone file playback are separate
delivery modes; this YAML does not secure those independent hosting services.

## Verification scope

The CMD launcher was executed from outside the project directory. Initial creation
and replacement of an existing YAML succeeded. A deliberately missing required
port produced a nonzero exit code and left the previous YAML byte-for-byte
unchanged; valid configuration was restored and generation succeeded again. The
generated text contains two disjoint routers, HTTP loopback ports 9000/9001 and
preserved Host handling, without external-authentication or TLS settings.

Only the text generator and its YAML output may be checked for this integration.
No application test suites, builds, services, browsers, containers or proxy are
started. Successful generation does not establish runtime reachability, asset
loading, streaming behavior, external authentication or central deployment safety.
