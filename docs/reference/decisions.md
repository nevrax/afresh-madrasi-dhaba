# Behavior decisions and unresolved parity

No item marked **open** can be used as evidence of complete runtime parity. The implementation now combines extracted source rules, native regression tests and bounded observations in pinned Ruffle 0.6.0. [Reference observations](../../tests/reference/observations.json) distinguish unmodified canonical runs from instrumented derivatives and list their controlled overrides. The derivatives retain every canonical SWF tag and append one instrumentation action. These are emulator observations, not measurements in historical Adobe Flash Player. No third-party score submission has been used as a test.

| ID | Status | Evidence / policy | Required resolution |
|---|---|---|---|
| D-001 | Established native ordering policy; cross-runtime timing equivalence open | Native uses integer thirds of a millisecond for 12 Hz cadence/deadlines and synchronous commands after previously advanced events. A stable min-heap orders jobs by exact `(at,id)`, retaining FIFO registration order at equal deadlines. Generation cleanup rebuilds retained global jobs without changing deadlines/IDs; callback limits and orphan semantics are unchanged. Queue tests compare interleaved operations against the previous sorted-array oracle, alongside existing timing/lifecycle tests. Reference cooking/serving/full-day samples do not establish every first-frame phase or simultaneous callback tie. | Keep first-frame origin, action-queue timing and equal-deadline ordering explicit. The heap is a storage change, not new clock semantics or proof of whole-game performance improvement. Additional runtime comparisons must distinguish timestamp samples from actual callback ordering. |
| D-002 | Ruffle minimum established; native batching policy explicit | `(16−day*2)*1000` reaches zero at day 8 and becomes negative. Default is now **10 ms**, configurable by option, with `non-positive-spawn-interval` diagnostic and no day cap. Pinned Ruffle timer source clamps to 10 ms; a coordinator-observed zero/negative timer burst was consistent with that minimum. Native runs all due callbacks in deterministic order, whereas Ruffle limits work per update and does not promise FIFO ties. | Do not describe native long catch-up batches or all day8/9 scheduling as identical to Ruffle or Adobe Flash. See the pinned timer source linked below. |
| D-003 | Implemented source fallback and observed reuse semantics | The 100-attempt identity/table searches and occupied-identity fallback remain source-derived and regression-tested. Repeated source `Appear` calls in Ruffle confirm that overwriting a timer handle leaves the previous interval active. Native retains old table records, current character pose, overlapping timers and cancellation of only the currently stored handles. | No protective invalidation or balance fix is applied. The probe controls `Appear` directly; it is not evidence of a naturally occurring 100-failure random sequence. Cross-screen rebinding is covered by D-007. |
| D-004 | Source event behavior implemented; full audible comparison open | Menu sound162 is emitted once. Gameplay retains ActionScript-selected music: pinned Ruffle queues DoAction execution but handles StartSound immediately, so the later queued stopAllSounds removes the competing root sound477. Muted startup still starts music; food/bill actions subsequently stop all sounds. Orders are guarded; `serve` is unguarded and lacks an exported sound. Food446 preserves loop20 at frame36 and loop15 at frame303. | Event tests and engine-source ordering support this implementation. Complete audible comparison, decoding/mixer behavior and historical Adobe Flash equivalence remain separate evidence requirements. |
| D-005 | Tutorial control/clock behavior implemented; full cycle observed | Original Start/HowToPlay/Skip callbacks were exercised without accelerating clocks. Tutorial321 naturally wraps335→1; persistent children continue: at parent335 radio199 is16 and nested198 is12, then at parent1 they are17/13. Native retains separate unbounded parent and child ages, advances while hidden on instructions, and rewinds only the parent on HowToPlay. Skip enters gameplay and ends both clocks. Reachable action exports contain only Skip, branding-click and child320's call to an undefined tutorial `CheckComplete`; no terminal stop or extra game rule was found. | The recorded full cycle and focused hidden/replay/loop/Skip tests close this control-flow gap. Complete pixel/effect/audio comparisons remain D-004/D-011/D-013; historical Adobe Flash timing is not claimed. |
| D-006 | Original form/protocol implemented; remote acceptance unverified | The source-positioned form restores `noname`, verbatim names and immediate hiding on submission. Native Rijndael verification matches the adapted source, with independent byte-input checks and request/error fixtures. Deployment-owned configuration defaults to no POST endpoints: Submit is disabled and explicitly says nothing was sent, as observed in the native browser. A configured response means received, not proven accepted; no result-code meaning is invented. | A compatible endpoint can be configured deliberately. Historical backend availability, session cookies and actual score acceptance remain unverified. Preserve visible unavailability and never substitute local storage for an online submission. No third-party test POST is needed to verify the isolated protocol. |
| D-007 | Implemented; removed/new-day path rebinding observed | StopGame clears arrival/clock jobs and the latest customer handles reached through table records. Overwritten function intervals retain their deadlines. Reference old-clip properties become undefined on frame7, then resolve to the new customer0 after Tomorrow; its hidden meter changes despite stored handle fields being0. Native preserves these global intervals, skips their inert bodies while gameplay clips are absent, and resolves the current customer ID after retry/next day. Session refresh remains global at 600000 ms. | Normal cleanup and orphan phase/rebinding have distinct regression tests. Do not restore blanket cancellation. The measured reference scenario is the documented repeated-Appear/next-day case, not every possible leaked callback combination. |
| D-008 | Established browser clock policy; historical equivalence open | Browser integration passes full RAF elapsed time to `advance(ms)`, including suspension gaps; it does not silently clamp or discard time. Blur or unexpected capture loss cancels an active pointer press once, preventing a stale release; it does not reset an idle carried item or pause the clock. Unsupported optional audio cannot abort gameplay, and actual resource/fatal errors get visible feedback. | Pointer lifecycle, autoplay and feedback contracts have adapter tests. Keep these separate from real-device/background-tab behavior, Ruffle update budgets and historical Flash timing. Browser visibility/high-density verification remains with the coordinator. |
| D-009 | Established native architecture and bounded decorative interpolation | TypeScript owns original domain clocks, state and callbacks; no Flash emulator or generic AVM is shipped. Only menu decoration146 and traffic204/206/210/215/218 interpolate compatible adjacent affine transforms/morph ratios. Other authored animation keeps 12 Hz sampling. Identity/replacement, visibility, masks, filters, color changes and loop boundaries stay discrete; buttons and filtered output keep source cadence. Cooking, patience, eating, tutorial and score clocks are unchanged. Integer-pose and boundary tests cover this presentation-only adaptation. | Rendering must not mutate domain state or alter gameplay deadlines. Interpolation is a native smoothing choice, not historical Flash frame equality. The rejected final-stage tile compositor lives only under `src/verification/` and is excluded from releases. Keep independent original child clocks and discrete boundaries. |
| D-010 | Established preservation rule | Surplus-plate patience gain, cash clamp, input-state oddities and per-character eating durations are retained. | Any future balance/bug fix must be a separate recorded change, not described as original parity. |
| D-011 | Native presentation implemented and bounded browser scenarios observed; full equivalence open | Original transforms, source-derived text, order masks, clock hands and separate parent/child playback are implemented. The native browser exercised cooking/hold/cancel/plate/serve/payment/exit, a full bot day, next day and three loss/retry cycles, with no missing assets reported. Manual game-over verified original form unavailability and publisher/retry controls. Seven GPU/CPU filter fixtures passed within the recorded pixel tolerances (D-013); these are not original-renderer comparisons. Fonts107/423 have no embedded outlines, and the native Submit skin is an approximation. | Exact historical pixels, text/font substitution, full scene/overlap hit semantics, audio decoding/listening and all-browser/device behavior remain unverified. Keep scenario observations distinct from pixel/audio equivalence and retain the device-font limitation. |
| D-012 | Separate optional local scores implemented | `LocalScores` remains a clearly labelled More options feature with browser-only save/list behavior, trimmed names, a 50-character limit and explicit storage failures. The source online form has its own controller, unrestricted names, protocol adapter and unavailable/sending/received/error states. Original publisher and highscore links require user activation. Local success never implies an online ranking. | No unresolved permission question blocks this separation. Configure a compatible service only when one exists and is deliberately selected; otherwise retain the explicit online-unavailable default. Online acceptance remains D-006. |
| D-013 | Native vector/group/filter composition implemented; historical pixel equality open | Paths, morphs, masks, source color transforms, reflected/focal gradients and button states compile into native drawing data. Gradients use their source coordinate transforms. Affected groups are isolated before blur/shadow compositing; separable fractional box filters preserve separate axes and premultiplied channels, using GPU processing with a CPU fallback. The coordinator observed [filter-check.ts](../../development/verification/filter-check.ts) pass 7/7 fixtures with 24 GPU passes: maximum alpha/premultiplied-channel error within 2/255 versus the CPU reference. Mean premultiplied error was at most 0.1278 byte. | This validates bounded GPU/CPU fixtures, not all game filters or historical Flash pixels. Keep full-scene, glyph, hairline and GPU/device comparisons explicit. The experimental symbol193 static suffix grouping failed composition pixel checks and is removed from production; its allocation improvement is not an accepted optimization. Source actions remain explicit TypeScript logic. |
| D-014 | Implemented; hidden-template bug observed | Source `mcDosa.Stop()` has an uppercase S and is undefined in the reference. The offscreen template plays, emits its sounds, removes itself at frame284 and applies the cash penalty at location1000,1000. A timely bowl click resets/stops it. If already removed, the source still changes pointer modes, but duplication cannot create food. Native `batterTemplate` preserves these rules. | Keep this original bug unless a later gameplay change explicitly changes it. The penalty/removal is runtime-observed; the unguarded failed-duplication branch is source-derived and regression-tested. |
| D-015 | Implemented; quantized patience observed | Patience is a MovieClip `_y` position. Each assignment truncates toward zero to twentieths of a pixel, including partial-service recovery. Fresh authored position is −65.9; OrderDosa explicitly resets it to −66. The ordered sequence includes −65.8,−65.6,−65.35; anger starts at callback118 and loss at160, ending at −29.85. Source placement and Ruffle traces support native boundary tests. | Do not replace this with unquantized Number increments or a fixed0.25 step. Both would change the rule. |
| D-016 | Implemented; independent food smoke observed | Cooked food contains unnamed child223 at depth9, placed at parent310 and removed485. Its 12-frame playback continues while parent food is held/frozen. Duplicating onto the plate resets the child to1 while preserving the parent pose; it then keeps playing. Native `smokePose` preserves this independently of parent cooking age and cancellation. | The cook-smoke trace and native tests cover pickup327, hold, duplicate and plated playback. This does not claim all presentation effects or pixels are equivalent. |
